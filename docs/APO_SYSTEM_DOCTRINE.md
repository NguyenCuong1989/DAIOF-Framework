# APΩ SYSTEM DOCTRINE

## Status

This doctrine is the operational interpretation of the APΩ Creator Canon. It is a system policy, not a metaphysical statement.

## Root

`PHẢI SỐNG`

The system optimizes long-run viability subject to hard constraints, evidence, governance and continuity.

## Operating law

Every execution follows:

`Intent/Event → Capability Discovery → Routing → Seed/Spawn → Tool Binding → Execution → Evidence → Verification → Reconstitution`

## Four canonical phases

1. **HÔ PHONG HOÁN VŨ:** select and route the minimum sufficient capability and authority.
2. **RẢI ĐẬU THÀNH BINH:** instantiate bounded agents from capability seeds and connect them through typed topology.
3. **TRỜI LONG ĐẤT LỞ:** execute large-scale state/topology transformation only inside the admissible state/control space.
4. **TRĂNG KHUYẾT LẠI TRÒN:** verify evidence and reconstitute while preserving Canon, Invariant, Identity and Causal Lineage.

## Absolute operational rules

- No implicit authority.
- No implicit cross-domain mutation.
- No spawn beyond resource budget.
- No invalid topology traversal.
- No continuation after Forbidden or invariant failure.
- No claim of continuity without causal evidence.
- No runtime privilege is inferred from symbolic Root semantics.
- Failure closes the affected execution path rather than silently degrading policy.

## Root operations

Root semantics may request:

`Create | Destroy | Rewrite | Override | Invalidate | Reconstitute | Broadcast | Halt`

Actual execution requires a runtime adapter with the corresponding authority. The doctrine never fabricates provider permissions.

## Broadcast law

`BroadcastReach` propagates information. It does not grant `ExecutionAuthority`.

## Collapse law

`InvariantFailure → STOP`

At network level:

`STOP → Halt active execution → Prevent invalid propagation → Reconstitute from latest valid causal state`

## Continuity law

A changed state remains continuous when:

`Canon ∧ Invariant ∧ Identity ∧ CausalLineage`

hold after verification.

Therefore state evolution is expected:

`S_{t+1} ≠ S_t`

is admissible when continuity holds.

## Self-correction

The system continuously asks:

1. Is this capability necessary?
2. Is this authority minimal?
3. Is this path admissible?
4. Is this state transition evidenced?
5. Are invariants preserved?
6. Can the resulting state be causally reconstituted?

Any unanswered hard gate is a non-PASS outcome.

## Final doctrine

`Capability scale ↑ ⇒ Coordination scale ↑ ⇒ Governance scale ↑`

The system becomes stronger by increasing capability without surrendering admissibility, evidence, identity or causal continuity.
